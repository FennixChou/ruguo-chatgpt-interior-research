如菓室內裝修｜內部研究報告

提升 ChatGPT 室內設計生圖能力：
GitHub 海底撈針研究（2026-08）

資料截止 2026-08-19｜掃描 94 筆、入表 81 筆、深讀 23 筆＋補掃深讀 13 筆｜經對抗把關複核

一、結論先行

GitHub 上沒有一個專案能讓 ChatGPT 本身變強。能撿的只有兩樣東西：別人整理好的提示詞結構，以及繞開聊天窗、直接呼叫官方生圖介面的操作台。

最值得做的 3 件事（補掃後版本）

  • 一手來源改用官方正本。以 openai/openai-cookbook 的生圖範例（Generate_Images_With_GPT_Image 與 Generate_Images_With_High_Input_Fidelity）當提示詞與參數的唯一準則，把 wuyoscar/GPT-Image2-Skill 的備份與「Architecture & Interior」圖庫降為對照。零成本，當天可做。
  • 先把「空間不准變」寫成固定的一段提示詞。抄 zyliu0/interior-design 的空間保真規則——鎖住牆體、窗戶位置與相機角度，只換材質、燈光與家具；這是補掃唯一明確走 OpenAI 生圖介面的室內設計專案，也直接對應目前出圖最常見的走位問題。
  • 自架出圖台，並補做一次引擎比較。用 alasano/gpt-image-playground 取得聊天窗給不了的遮罩局部改圖與每張成本可追溯（需自備金鑰並設密碼）；同時用同一組室內提示詞把 gpt-image-2 與 Google 的 Nano Banana Pro 並排比一次——競品提示詞庫的星數（10,245 與 13,231）已高過多數 gpt-image-2 庫，選型不該只憑習慣。

GitHub 上沒有什麼：沒有任何能微調（fine-tune）ChatGPT 或 gpt-image-2 的工具——官方不開放這個模型微調，所以這條路在開源界根本不存在。至於「室內設計專用專案」，補掃後修正原先的說法：確實存在，但可直接用於 ChatGPT 出圖的只有 zyliu0/interior-design 一個個人輕量專案（1 star、5 個檔案）；其餘室內專用工具（ArchAi3d、interior-designer-ai、sd-interior-design、decor8ai）全走 Qwen／Replicate／Stable Diffusion／商用 API 路線，只能抄結構、不能直接用。

本節已含補掃結果。

二、方法與把關

以六個角度在 GitHub 檢索（依命中結果歸納）：gpt-image-2／GPT Image 關鍵字族、提示詞庫與案例合輯、ComfyUI 節點與外掛、MCP 與 agent 技能串接、OpenAI 生圖 API 應用程式、學術方法與評測基準。合計命中 94 筆，去重與剔除明顯不相關後入表 81 筆，其中 23 筆逐一讀 README 做成深讀卡。

對抗把關結果：事實面抄得很準，判斷面出了 4 個問題

把關員逐張核對 36 張卡，全數存在；stars、最近更新時間、封存狀態逐一比對後只有 2 處微差（一張卡的最近更新差 2 天、YouMind 的星數差 1 顆）。也就是說，抓下來的數字可信；不可信的是掛在數字上的判斷。

問題一：假活躍抓到 4 個

最典型的是 ZeroLu/awesome-gpt-image——近 5 筆提交全是機器人 +1/-1 只改一行時間戳，最後一筆真人提交停在 2026-07-01 而且只是加了顆星星徽章，卻被判為活躍。YouMind 的 1.5 提示詞庫同樣是 +32/-32 純空轉、近百筆零真人。house_diffusion 全庫只有 3 筆提交、程式碼凍結在 2023，靠一筆 2026 的 README 註記詐出新的更新時間。另有 dontriskit（停更 6 個月）與 Azure visionary-lab（停更 5 個月）被高估。

教訓：最近更新時間只是「有人推過東西」，不等於「有人在維護」。要看的是最後一筆真人內容提交。

問題二：存活判準前後不一致

同一份清單裡，停更 15 個月的判「停更」、停更 15.5 個月與 16 個月的卻判「停滯」。本報告已統一收斂：停更逾 12 個月一律列停更，僅機器人活動列假活躍。

問題三：授權紅線漏判（本次最大的一個失誤）

avillabon/comfyui-gpt-image-2-artifact-cleaner 的授權是 PolyForm Noncommercial 1.0.0——禁止商業使用。如菓是營利設計公司，效果圖是客戶交付物，屬商業使用，這條是禁令不是「留意事項」。原掃描把這個唯一不能合法使用的工具排到實用分 8，本報告下修為 3 並列為不採用。它也不會生圖（純本機後處理），原標示「使用 OpenAI 生圖」是錯的；真正的模型出自上游 Larryvrh/gpt-image-2-artifact-cleaner，這個是包裝層，8 筆提交全集中在同一天。

問題四：有沒有室內設計內容，沒有實際核過

xianyu110 全文檢索後完全沒有室內設計類目，實用分由 7 下修為 5；YouMind 的「Architecture / Interior」只是一條指向自家商業網站的外部連結，庫內並無該分類內容。反過來，wuyoscar 是被低估：它真的有室內專館、也真的直打官方生圖與編輯端點。

三、Top 10 精選（含補掃後重排）

五、方法論萃取：16 條可搬到 ChatGPT 的具體技巧

以下是把各專案裡的做法剝掉技術外殼後，直接能用在如菓日常出圖的操作原則。不需要裝任何東西就能用。第 13–16 條為補掃新增。

#技巧怎麼落到提示詞或流程出處
1提示詞用五段式，不要寫成一段散文任務類型 → 主體描述 → 風格定義 → 技術參數 → 輸出規格，五段各自獨立成句。同一個案子換風格時只改第三段，其餘不動，出圖差異才可歸因。xianyu110/awesome-gptimage2
freestylefly/awesome-gpt-image-2
2先講空間，再講畫面先用文字把格局、動線、家具位置與朝向講清楚，再要求出圖；把「佈局」當成獨立條件而不是形容詞。這正是 layout-to-image 研究把版面獨立成輸入的道理。ZGCTroy/LayoutDiffusion
aminshabani/house_diffusion
3能給參考圖就別從零生成以現場實景照當條件輸入，模型負責換材質與陳設、不負責重新想像格局。這是「保格局換風格」的正解，也是結構條件控制方法的原始命題。lllyasviel/ControlNet
Nutlope/roomGPT
4局部要改就用遮罩，別整張重生只框出要改的區域（例如電視牆、地坪）送編輯端點，其餘畫素原封不動。整張重生會連客戶已經點頭的部分一起改掉，是反覆改圖的主因。alasano/gpt-image-playground
ControlGenAI/MaterialFusion
5材質詞要連光一起寫「霧面橡木」單獨寫沒有用，要連同光從哪來、反射強弱一起描述。材質替換研究之所以強調光照感知，就是因為材質的說服力來自光而不是名詞。ControlGenAI/MaterialFusion
astra-vision/MatSwap

PicoTrex/GPT-ImgEval
11每張圖的成本要能追溯生圖按次計價，介面層要把每次呼叫的參數與花費記下來，才能算進案子成本、也才知道哪種尺寸解析度划算。alasano/gpt-image-playground
12出圖要配資產管理與品質檢查成熟的生圖流程不是只有生成，還有提示詞優化、品質檢查、標籤與版本管理三段；沒有這三段，圖多了就找不到、也說不清哪張給過客戶。Azure-Samples/visionary-lab
13用一段「不可違反」的主提示詞鎖住空間骨架在每一則室內提示詞最前面固定放同一段話：牆體位置、開窗位置與大小、相機角度與鏡頭高度一律不得更動，只准更換材質、燈光與家具陳設。這段話不隨案子改寫，改的只有後面的風格段。走位問題多半是因為沒有把「不准變的東西」寫成硬條件。zyliu0/interior-design（補掃）
14改圖分三段講：先移除、再繪製、最後才是可選項把改圖指令拆成「要移除什麼」「一定要畫成什麼」「哪些是可選的加分項」三段分別寫清楚。混在一句裡講，模型會把可選項當必要項、把保留項當可改項，這是改圖來回輪數失控的主因。amir84ferdos/ComfyUI-ArchAi3d-Qwen（補掃）
15材質先建分類表，再寫進提示詞把常用材質先依大類（石材／木皮／金屬／織品／塗裝）建成一份固定清單並統一命名，寫提示詞時直接引用清單裡的名稱，而不是每次臨場想形容詞。命名統一了，出圖差異才能歸因到材質本身；那套工具箱正是靠 103 組材質預設在做這件事。amir84ferdos/ComfyUI-ArchAi3d-Qwen（補掃）
16照官方參數表逐項對帳，別只調提示詞官方範例列出的參數（例如輸入保真度、尺寸、品質等級）會實質改變出圖結果，卻常被整段忽略、只在文字上打轉。拿官方參數表對現行流程逐項打勾，補齊沒用到的，往往比再改十版提示詞有效。openai/openai-cookbook（補掃）

八、把關員指出的缺口與下一步

缺口一（已補）：整份掃描漏掉一手來源

openai/openai-cookbook（75,345 stars，今日仍在更新）裡的 examples/multimodal/image-gen-models-prompting-guide.ipynb，才是 gpt-image-2 提示詞的權威正本。本次排到實用分 9 的那份指南，自己就標明是「distilled from」它。掃描把二手轉述排到第一，卻整份漏掉一手來源。

補掃結果：已補讀，見第三之二節 S01。官方範例集今日仍在更新（75,345 star、MIT 授權），已升到本報告 Top 10 第 2 名，二手備份正式降為對照。剩下要做的只有把官方參數表逐項對進如菓現行流程（第五節第 16 條）。

缺口二（已補）：沒下「interior design / virtual staging」這組英文關鍵字

六個搜尋角度全繞著 gpt-image 與提示詞打轉，沒有把室內設計與虛擬佈置當成獨立的一組英文關鍵字去搜。清單裡那些室內相關專案，是從其他角度旁掃到的，涵蓋率沒有保證——這也解釋了為什麼命中的室內工具幾乎全是 Stable Diffusion 路線：真正對口的那批可能根本沒被搜到。

補掃結果：已補掃，見第三之二節，深讀 13 筆、另列名 5 筆。結論證實了原本的懷疑，但方向要修正：室內設計專用專案確實存在且活躍（ArchAi3d、interior-designer-ai、sd-interior-design、decor8ai、arcada），只是幾乎全走 Qwen／Replicate／Stable Diffusion／商用服務路線；真正走 OpenAI 生圖介面的室內專案只有一個 1 star 的個人專案。原報告「沒有現成的室內設計專用專案」這句話因此修正為「有，但只有一個能直接對接」。

缺口三（仍未補）：從沒做過一次引擎並排比較

補掃撞見一件必須正視的事：Google Nano Banana Pro 的兩個提示詞庫合計 23,476 star（13,231＋10,245），已高過本報告任何一個 gpt-image-2 庫，而且其中一個有現成的室內設計專章。至今沒有任何一次用同一組室內提示詞把兩邊並排比過，選型等於憑習慣。

下一步：挑 3 個真實案場的實景照，用同一組提示詞各出 3 張，依格局保真、材質說服力、光影自然度、改圖輪數四項打分，做成選型依據。

缺口四（仍未補）：三個可用專案的授權都還沒確認

補掃裡實用分不低的三個專案——去瑕疵模型上游（Larryvrh）、室內工具箱（ArchAi3d）、虛擬佈置平台樣板（SamurAIGPT）以及節點集合（Aryan185）——授權欄位全是未標示或未明確聲明。如菓的效果圖是客戶交付物，屬商業使用，未標示授權不等於可以自由使用。

下一步：任何一個要進生產流程前，先向作者取得書面授權說明；取不到就當成不可用，改以自有管線實作。這條與第二節「問題三」是同一個教訓，不要再犯第二次。

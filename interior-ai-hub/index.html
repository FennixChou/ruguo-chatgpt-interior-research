這份文件是什麼：GitHub 上跟「室內設計 AI 生圖」有關的專案工具、提示詞庫、資料集，一次盤點成一個可以逛的專區。108 個獨立項目，每個都標清楚是什麼、對如菓能做什麼、要不要 GPU 或 API 金鑰、上手多難、老闆的 RTX 4060 8GB 跑不跑得動。

資料怎麼來的：六路研究員並行擴掃 GitHub，共回收 121 筆，依 URL 去重後 109 筆，再逐筆連線核實，其中 1 筆 HuggingFace 倉庫回傳 401、一般使用者無法公開訪問，當場剔除，最終 108 個獨立項目。所有星數與最後更新日期都是 gh api 逐筆核實的當日值，不是憑印象。少數非 GitHub 來源（Civitai 模型頁、HuggingFace 倉庫）沒有可核實的星數與更新日，一律標「需確認」。

用途判斷的責任歸屬：表格內「如菓用途」欄與各章的取捨建議，全部是（賈維斯判斷），不是 repo 作者的宣稱。作者原文宣稱一律放在「一句話功能」欄。

0. 結論先行

  1. 本機 ComfyUI 是主力，不用改路線——108 筆掃下來，沒有任何工具能取代老闆現有的 img2img + ControlNet depth + IPAdapter 流程，能做的是在同一條流程上加零件，不是重來。
  2. 三個零件裡有兩個已經在機器上了，真正要補的是 MLSD 與 inpaint——本輪實測 ComfyUI根目錄/custom_nodes 已裝 comfyui_controlnet_aux、ComfyUI-IC-Light、ComfyUI_IPAdapter_plus、ComfyUI-GGUF，而且現有 workflow 已在用 DepthAnythingV2Preprocessor＋controlnet-depth-sdxl-1.0-fp16。所以要補的只有兩件：MLSD 直線控制（節點已有，但 SDXL 的 MLSD ControlNet 權重本機沒有、得另外下載，見 B-2）與 comfyui-inpaint-nodes 局部重繪。合計約 6–7 小時裝完＋測完（ComfyUI-Manager 0.5 h、IC-Light 接線 0.5 h 另計）。
  3. 老闆自己能操作的介面出現了——Acly/krita-ai-diffusion（10,538★，8/28 剛更新）把 ComfyUI 藏在 Krita 後面，用畫筆圈家具位置就能換款，不用碰節點圖。這是本輪對「非工程師老闆」價值最高的單一發現。
  4. 效果圖打光是被忽略的加分項——kijai/ComfyUI-IC-Light 一鍵裝進現有流程，交屋實景照可以重新打光營造氛圍，不用重拍現場。SD1.5 底模，8GB 卡輕鬆跑。
  5. 提示詞方面最強命中不是大清單，是小庫——qzh3722/awesome-nano-banana-spatial-design 只有 13★，但按「概念發想／平面規劃／技術轉視覺／材質風格／渲染」分類、中英雙語、且收了完整的「保格局換風格」提示詞逐字稿，比 27,632★ 的 freestylefly/awesome-gpt-image-2 實用十倍（後者的「建築與空間」分類經查證多為城市地圖與海報，非室內）。
  6. 平面圖轉 3D 有一條免費、CPU 就能跑的新路，但門檻比看起來高——Yytsi/floorplan-to-3d（19★，MIT）把平面圖切出牆門窗後在瀏覽器裡擠出 3D 量體，只出量體無材質，當客戶溝通的簡報素材夠用。注意：官方線上 demo（floorplan-to-3d.pages.dev）只能看三張預先算好的官方範例、沒有後端，不能上傳自己的圖；要測自己的案場圖必須本機部署，而且輸入是 CubiCasa5K 格式的 SVG（靠 cairosvg 轉點陣），不是手繪或掃描的 JPG／PDF。
  7. Sweet Home 3D 可以讓賈維斯直接下指令畫格局——sweethome3d-mcp-server（36★）把免費室內設計軟體變成 MCP 工具，多視角出圖靠 MCP 自己的 set_camera＋render_photo，SH3D-ConsolePhotoGenerator 則負責把既有檔批次重算成高品質圖（它一個檔一次一張、視角取自檔內已存相機，不負責換視角），全程零 API 金鑰、零 GPU。
  8. 授權要當紅燈看——本輪 108 筆有 41 筆授權未標示或需人工核實（31 筆完全無 LICENSE、4 筆 NOASSERTION、5 筆只標 Other 未細查、1 筆標示矛盾——decor8ai-sdk README 標 MIT 但 GitHub 偵測 NOASSERTION）。沿用 8/19 教訓：如菓是營利公司、效果圖屬商業使用，授權未標示一律先當不可用，要用先開 LICENSE 檔核實或洽作者。
  9. Flux 系列現在別碰——Flux Kontext 的局部重繪節點（ComfyUI-Kontext-Inpainting、flux-kontext-diff-merge）技術路線正是如菓要的「只改該改的地方」，但標準精度需 16GB+ VRAM，8GB 要靠 GGUF 量化且效果未實測。列入觀察，不列入本季行動。
  10. 自訓練 LoRA 現階段不做——GitHub 上找不到成熟的公開室內設計 LoRA 成品（權重都在 Civitai／HuggingFace），要自己練得先備素材＋20 小時以上，投報比輸給「先把現有 workflow 調好＋抄好提示詞」。

A 一鍵工具與開源 SaaS（24 筆，本章列 12）

白話導讀：這一類是「別人已經做好的成品」——上傳一張房間照、選個風格、按一下、出效果圖的網頁 App。壞消息是：幾乎全部要 API 金鑰。它們自己不會生圖，是把圖丟給 Replicate、fal.ai、Decor8.ai 這些雲端服務去生，所以老闆決定不開金鑰的前提下，這一類沒有一個能直接拿來用。

那為什麼還要收？兩個理由。第一，介面與流程可以抄——客戶要的是「選風格→看結果→換一版」這種簡單體驗，不是節點圖，這些專案已經把這件事的 UI 做過一輪了。第二，有三個例外真的能本機跑：zaozuohuabu-windows-preview（Windows 本機 AI 畫布，可接自己的 ComfyUI）、Daniil-Horobets/MyInterior-AI（Docker 化的 SD+ControlNet 草圖轉效果圖管線）、alaradirik/sd-interior-design（Realistic Vision + 分割/MLSD 雙 ControlNet，跟老闆本機 SD1.5 備援同家族）。

另外注意本類的授權狀況特別差——24 筆裡有 9 筆完全沒有 LICENSE 檔，包含兩個看起來最完整的 SaaS 骨架（ai-room-declutter、ai-real-estate-stager）。要拿它們的程式碼商用，得先寫信問作者。

B ComfyUI・SD 工作流與節點（29 筆，本章列 15）

白話導讀：這是老闆最該看的一類——29 筆裡 14 筆判定本機 8GB 卡直接跑得動、14 筆調整後可跑（多半是換量化模型或降解析度）、只有 1 筆完全不行，而且多數是 ComfyUI Manager 點一下就裝好的節點包，不用寫程式。

這類東西解決的是同一個問題：「AI 換風格的時候，不要把我的牆、窗、格局一起改掉。」 手法有三層：

  1. 結構抽取層——先從實景照抽出空間骨架，再叫模型照著骨架畫。comfyui_controlnet_aux（MLSD 直線偵測、Depth、Canny、Seg 全包）跟 ComfyUI-DepthAnythingV2（深度估計升級版）就是幹這個的。老闆現在用的是 depth，加上 MLSD 之後牆線門窗線會更穩，因為 MLSD 專門偵測直線段，室內場景全是直線。但注意：這兩個節點包只提供「前處理器」（把照片畫成骨架圖），吃骨架圖的 ControlNet 權重要另外下載，詳見 B-2。
  2. 局部重繪層——不要整張圖重生，只框選要改的那塊。comfyui-inpaint-nodes 提供 Fooocus 的 SDXL inpaint 模型與 LaMa／MAT 填補工具，換一張沙發不會動到地板。
  3. 差異融合層——AI 改完之後，只把「真的有變的區域」貼回原圖，其餘畫素用原照片。flux-kontext-diff-merge 專攻這件事，是保格局的最後一道保險。

另外兩個加分項：ComfyUI-IC-Light（重新打光，交屋照可以改成自然光氛圍）跟 Acly/krita-ai-diffusion（把 ComfyUI 藏在畫圖軟體後面，老闆自己就能操作）。

要避開的：Flux 系列（x-flux-comfyui、ComfyUI-Kontext-Inpainting、flux-kontext-diff-merge）技術方向完全正確，但標準精度要 16GB+ VRAM，8GB 卡要靠 GGUF 量化且效果未實測——列入觀察，本季不動。研究級原始 repo（lllyasviel/ControlNet、navervision/mlsd、LiheYoung/Depth-Anything）不用碰，它們的能力已經被上面的 ComfyUI 節點包好了。

C 平面圖與 3D（19 筆，本章列 10）

白話導讀：這一類分成三個完全不同的問題，別混在一起看：

  1. 「舊平面圖怎麼數位化」——客戶丟一張掃描的、手繪的、PDF 截圖的平面圖，怎麼變成電腦看得懂的牆／門／窗／房間。工具：TF2DeepFloorplan（268★，已訓練好的模型，CPU 也能跑）、Raster-to-Graph（64★，2024 論文，輸出可編輯的結構化格局）、FloorplanTransformation（679★，2017 經典但環境老舊難裝）。
  2. 「平面圖怎麼變 3D」——Yytsi/floorplan-to-3d（19★，MIT）最實用，CPU 就能跑，但線上 demo 只能看三張官方預算好的範例、不能上傳，且輸入格式是 SVG 不是照片（詳見 C-2）；plan2scene（610★）能給材質但停在 2021、學術 demo 等級。
  3. 「AI 能不能幫我排格局」——Graph2plan（347★）、house_diffusion（234★）、Floor_Plan_Generation_using_GNNs（85★）都在做這件事，但全部是研究級程式碼，且訓練資料是大陸 RPLAN 住宅（8 萬筆），格局習慣跟台灣有落差。當發想參考可以，當生產工具不行。

還有一條本輪新發現、跟上面三條都不同的路線：Sweet Home 3D + MCP。免費的室內設計軟體 + 一個讓 Claude 直接操控它的外掛，賈維斯可以直接畫牆、擺家具、批次出圖——零 API 金鑰、零 GPU、零學術程式碼。這是本類最務實的一支。

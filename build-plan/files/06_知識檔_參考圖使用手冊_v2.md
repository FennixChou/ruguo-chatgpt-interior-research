# 06_參考圖使用手冊

本檔用途：定義如菓室內設計出圖時，參考圖要怎麼分類、怎麼在 prompt 裡指涉、怎麼拍才有用，以及出圖失敗時的處理方式。給 GPT 讀（判斷邏輯）也給老闆讀（怎麼準備照片）。

---

## 一、參考圖三分類

出圖前先判斷手上的照片屬於哪一類，不同類用途不同：

### 1. 實景照（Actual Room Photo）— 格局鎖定
- **用途**：告訴 GPT「這是真實空間，牆、窗、樑、門的位置不能變」。
- **prompt 指涉方式**（範例）：
  > "Image 1 is the actual room: keep the layout, window positions, beam positions, and door positions exactly as shown. Only change the finishes and furniture as described below."
- **何時用**：客戶要「保格局換風格」的效果圖，或任何實體案場的翻新提案。

### 2. 材質特寫（Material Close-up）— 質感鎖定
- **用途**：指定某一種具體材質的紋理、色調、光澤，避免 GPT 自由發揮出塑膠感貼圖。
- **prompt 指涉方式**（範例）：
  > "Image 2 shows the exact wood tone and grain to use for the flooring — match this texture and color, not a generic wood."
- **何時用**：客戶指定某款建材（木紋、磁磚、石材、布料）要精準複製質感時。

### 3. 風格圖（Style Reference）— 氛圍鎖定
- **用途**：傳達整體色調、光線氛圍、家具語彙、軟裝搭配的「感覺」，不鎖定具體格局或材質。
- **prompt 指涉方式**（範例）：
  > "Image 3 is a style reference for overall mood, color palette, and furniture style only — do not copy its room layout."
- **何時用**：客戶說「我想要像這張圖的感覺」但空間本身不是這張圖時。

### 4. 平面圖（Floor Plan）— 格局權威依據
- **用途**：唯一的格局權威來源，用來把平面圖變 3D（模式二）；不是風格參考，也不是要保留原貌的實景照。
- **prompt 指涉方式**（範例）：
  > "Image 1 is the floor plan — the sole authority for room count, wall positions, door and window locations. Use only the geometry (walls, doors, windows, dimensions); ignore any text labels, furniture symbols, or annotations printed on the plan."
- **何時用**：只在模式二（平面圖轉 3D）啟動時上傳，且第一輪一律先用中文複述格局、不生圖。完整兩段式問答流程、45 度俯角參數、P-2／P-4 模板細節查 08 檔。

**一次使用建議 2–4 張最穩**：通常「1 張實景照＋1–2 張材質特寫＋1 張風格圖」的組合最容易得到可控結果。超過 4 張容易讓 GPT 混淆優先順序。平面圖（第 4 類）性質特殊，單獨使用、不與前三類混搭在同一次生圖裡。

## 二、實景照拍攝建議

拍出好用的實景照，是保格局出圖成功率的關鍵：

- **站門口拍**：站在空間入口處，確保完整看到空間全貌與比例關係。
- **眼高水平**：相機拿到約 120cm 高度（成人站立眼高），鏡頭保持水平，不要仰角或俯角。
- **開燈**：室內燈全開，避免陰影吃掉細節（門框、踢腳板、插座位置容易被陰影誤判消失）。
- **收雜物**：拍照前先簡單收一下地上、桌面雜物，減少 GPT 誤判「這是要保留的物件」。
- **拍全景＋兩側角**：至少 3 張——正面全景 1 張、左右兩側各 1 張斜角，讓 GPT 能拼湊出完整格局關係（樑的走向、窗的相對位置）。

## 三、不變/要換清單範本

每次出圖前，用一行寫「不變」、一行寫「要換」，貼在需求裡：

```
不變：保留原始窗戶位置、樑柱位置、門的開口方向、天花板高度
要換：牆面塗料改淺灰色、地板改淺色木地板、沙發與茶几全部換成北歐風款式、去掉現有的深色窗簾
```

原則：
- 「不變」寫具體構造元素（牆、窗、樑、門、天花高度），不要只寫「格局不變」這種抽象講法——GPT 對抽象詞的遵守率較低。
- 「要換」寫具體材質／色調／家具風格，避免只寫風格名稱（如只寫「北歐風」），最好搭配 04 風格定義的關鍵字一起帶入。

## 四、Edit / Inpaint 判斷樹

決定要用哪種生圖操作：

```
需求是什麼？
├─ 整體換風格（牆、地、家具、軟裝全換，但格局不變）
│   → 用實景照當參考「重生」整張圖（edit，多圖參考：實景照＋風格圖＋材質特寫）
│
├─ 只換一項（例如只換檯面材質、只換一面牆的顏色）
│   → 用 inpaint / mask：畫出要改的區域（mask PNG 同尺寸，透明區＝要改的區域），其餘部分不動
│
└─ 需要多角度輸出（同一空間要出正面＋側面兩張效果圖）
    → 兩次生圖共用同一組「材質規格說明」（materials block：牆面漆色、地板材質、主要家具款式寫成固定一段文字），
      分別套用到不同角度的實景照上，確保兩張圖材質一致
```

## 五、失敗處理

| 失敗症狀 | 處理方式 |
|---|---|
| 格局跑掉（牆消失、窗變位置、樑不見） | 加強 "keep unchanged" 語句的具體程度（明確點出每個構造元素），並縮小這次要求改動的範圍（一次只改材質，不要同時要求換格局氛圍） |
| 比例怪（家具過大/過小、走道看起來太窄或太寬） | 在 prompt 補上具體尺寸數字（引用 03 台灣住宅尺度與鏡頭幾何，例如「沙發座高 40–45cm、走道淨寬 ≥90cm」），讓 GPT 有數值錨點 |
| 材質看起來假（塑膠感、貼圖感） | 補上質感詞（如「霧面」「木紋走向自然」「布紋皺褶」）＋附上材質特寫參考圖，不要只靠文字描述 |

若同一張圖修正兩輪仍不過關，換掉這輪的參考圖組合重來，不要在同一組參考圖上無限修正。

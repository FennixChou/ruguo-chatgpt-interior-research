## A｜本機 ComfyUI 掛 ComfyUI-ArchAi3d-Qwen 試跑步驟與驗收

**它是什麼**：amir84ferdos/ComfyUI-ArchAi3d-Qwen（68 star，2026-04-17 更新，室內設計專用 ComfyUI 節點包），內建 103+ 組材質預設、相機控制、設計師人設系統提示、三段式改圖邏輯。**生圖引擎是 Qwen，不是 OpenAI**——如菓不打算換引擎，只抄它的結構。授權未標示（NOASSERTION），完整流程檔需付費訂閱才拿得到。

**試跑步驟**：
1. 本機 ComfyUI 安裝該節點包，先確認能正常載入、**不影響現有管線**（這一步優先，出問題立即停手）。
2. 只取三樣東西：103 組材質預設清單、空間保真規則、三段式改圖邏輯（先講移除什麼、再講畫什麼、最後講可選項）。
3. 把材質清單依五大類（石材／木皮與木地板／金屬／織品／塗裝）重整成如菓自己的中文命名表，名稱統一，不臨場想形容詞。
4. 用這份命名表寫 5 則提示詞，拿到**官方 gpt-image-2 生圖介面**上實測（不是在該工具箱的 Qwen 引擎上出圖）——這一步是驗收重點，材質詞要在官方引擎上有效才算數。
5. 有效就把命名表併入 05 知識檔的 B-4「材質五大類命名表」；付費流程檔不購買，只用免費節點裡拿得到的部分。

**驗收指標**：整理出 ≥40 組常用材質的中文統一命名；抽 5 組實測，材質外觀與命名相符者 ≥4 組。

**停損條件**：節點安裝影響現有 ComfyUI 管線，或免費部分被付費牆擋住拿不到材質清單，即刻停手，改由 05 檔既有材質詞彙表（02 檔）自建。

**授權提醒**：只搬「材質分類與命名方法」這類作法，**不把它的檔案內容複製進客戶交付物**。

## B｜gpt-image-playground 部署（需自備 API key）

**它是什麼**：alasano/gpt-image-playground（244 star，2026-06-21 更新，可自架的官方生圖／改圖操作台），可一鍵部署，內建**遮罩編輯**與**成本追蹤**兩個核心功能。走的是官方 gpt-image-2 端點，不是轉售商。

**用途只有兩個，不擴大範圍**：
- **mask 局部改圖**：只框出要改的區域（例如電視牆、地坪）送編輯端點，其餘畫素原封不動——解決「整張重生會連客戶已點頭的部分一起改掉」這個反覆改圖的主因。
- **成本追蹤**：生圖按次計價，介面層把每次呼叫的參數與花費記下來，累積成本可回溯，也能算進案子的作業時間評估。

**部署步驟**（只寫步驟，不寫金額）：
1. 確認 OpenAI 組織驗證已完成——未完成無法呼叫生圖模型，這是最容易卡住的一步，放第一步做。
2. 部署一份自架出圖台，**務必同時設定存取密碼**（預設部署是公開的，等於把金鑰交給任何拿到網址的人）。
3. 在服務後台為這把金鑰設每月用量上限，避免誤用暴衝。
4. 挑一個真實案子跑完整流程：整張生成 → 客戶回饋 → 用遮罩只改指定區域 → 定稿。
5. 全程記錄每張的參數與花費，跟現行 ChatGPT 網頁流程比對出圖品質、改圖輪數與總花費。

**驗收指標**：局部改圖時被改區域以外的畫面維持不變（格局保真五項檢核 5/5：牆體位置／開窗位置與大小／門洞位置／相機角度與鏡頭高度／地坪範圍）；同一案子的改圖輪數低於現行流程（現行輪數需先記一次當基準）；每張圖都有可查的成本紀錄。

**停損條件**：組織驗證兩週內過不了，或試跑一個案子的生圖花費高於它省下的改圖工時價值，就收掉自架台、回 ChatGPT 網頁流程。

## C｜路線 C（報告② 分類）白模工具（依報告②第 06 節事實）→ ChatGPT 上材質的 SOP

**先講清楚這條線的真實狀況**：報告②查證後的結論是——「白模截圖再交 ChatGPT 上材質」這條串接**本次調研無任何來源實測佐證**。以下工具本身「出真 3D」是官網明示的事實，但串接 ChatGPT 這一步是如菓要自己第一次試出來的，不是抄現成做法。

**吃平面圖出 3D 的事實核對表**（依報告②第 06 節）：

| 工具 | 吃平面圖出 3D？ | 免費額度 | 與 ChatGPT 怎麼搭 |
|---|---|---|---|
| Planner 5D | 是——出可編輯互動 3D 專案（真 3D，非圖片） | 每人一次免費試用 | 吃 DWG／DXF，對現有 CAD 圖友善；用它建幾何，用 ChatGPT 出氣氛示意圖 |
| CubiCasa | 是——手機掃描空間出 3D，輸出 DWG／DAE／FBX／OBJ | 需確認 | 現場沒圖時用它掃出平面圖，再餵 ChatGPT 生示意圖 |
| Floorplanner | 是——線上繪 2D 後可切 3D 檢視 | 免費 5 專案（限 3 層樓／3 設計，SD 輸出帶浮水印） | 需自己畫，不是上傳即轉 |
| HomeByMe | 是，但由平台設計師**人工**轉製、非純自動 | 免費帳號 2 專案、5 張擬真渲染 | 品質較穩但要等人工，急件不適用 |
| Getfloorplan | 宣稱是——2D／3D／360 導覽 | 需確認（**價格與工期本報告未能覆核，不得當已知數**） | 外包型服務，與 ChatGPT 無串接，列對照組 |
| Coohom AI Floor Planner | **否**——查證後只出可編輯 2D 平面圖（可移牆／改尺寸／增刪門窗），**不出 3D** | 免費方案起，至最高一級 | 前處理：把手繪或拍照的髒平面圖洗成乾淨 2D，再餵 ChatGPT |

**SOP（分兩段，別混）**：

*前處理段（現在就可以做，Coohom）*：
1. 手繪或翻拍的髒平面圖，先上傳 Coohom 免費方案，用它移牆／改尺寸／增刪門窗的編輯功能洗成乾淨的可編輯 2D。
2. 匯出乾淨版平面圖（無尺寸線、無浮水印、無案名文字）。
3. 依 08 知識檔的七步流程走 ChatGPT 模式二（先複述格局確認、再生圖）。

*白模試辦段（短期試辦，Planner 5D／Floorplanner）*：
1. 取一張已知格局的平面圖，若有 CAD 圖走 Planner 5D 的 DWG／DXF 匯入（一次性免費試用）；沒有 CAD 圖用 Floorplanner 免費 5 專案自己畫。
2. 建出 3D 白模，匯出等角或指定視角的截圖（不含材質、不含家具，純幾何）。
3. 把這張白模截圖當參考圖，連同 08 檔 P-4 參數化填空模板貼進 ChatGPT，指定材質光影，出效果級成果。
4. 對照直接用平面圖走模式二出的結果，比較兩者格局保真度與材質真實感——這是驗證「串接是否值得」的關鍵一步，因為目前沒有任何來源證明這條路比直出 ChatGPT 更好。

**驗收指標**：白模截圖版與直出版各出 3 張，格局保真五項檢核逐張比較；若白模版沒有顯著優於直出版（差距 <1 分／5 分制），本項到此為止，不再投入。

**停損條件**：Planner 5D／Floorplanner 免費額度（3 層樓／3 設計）用完前得出結論；若結論是「不比直出好」，保留 Coohom 前處理段（確有實測價值：清髒圖），放棄白模串接段。

## D｜gpt-image-2 vs Nano Banana Pro 引擎並排比較的測試設計

**為什麼要做**：Google Nano Banana Pro 的兩個提示詞庫（YouMind-OpenLab/awesome-nano-banana-pro-prompts 13,231 star＋ZeroLu/awesome-nanobanana-pro 10,245 star）合計 23,476 star，已高過本報告任何一個 gpt-image-2 庫，且 ZeroLu 那份有現成的室內設計專章（含「2D 平面圖→多視角效果圖＋3D 俯視平面圖」拼板結構）。至今沒有任何一次用**同一組室內提示詞**把兩邊並排比過，選型等於憑習慣。

**測試設計**：
1. 挑 3 個真實案場的實景照（建議客廳、主臥、廚房各一），代表如菓最常出的三種場景。
2. 寫**同一組提示詞**（含空間保真主提示詞開頭，即 08/05 檔的骨架句），兩個引擎各出 3 張，合計 **8 組共 16–18 張**（依案場數微調，報告①原案為 3 案場×3 張×2 引擎＝18 張；若時間有限可壓成 8 組室內提示詞×各 1 張×2 引擎＝16 張）。
3. 用固定評分表逐項打分，每項 1–5 分，同一人同一天評完，避免標準漂移：

| 評分項 | 說明 |
|---|---|
| 格局保真 | 牆體、開窗、門洞位置是否守住 |
| 材質說服力 | 木紋、石材、布料、金屬質感是否真實不重複 |
| 台灣感 | 是否誤畫西式壁爐、天窗、歐規插座等台灣住宅不會有的元素 |
| 光影自然度 | 光源方向與陰影是否合理 |
| 文字正確 | 畫面內若有文字（招牌、標籤）是否正確 |
| 可用度 | 整體是否可直接交付或需大改 |

4. 記下每張的花費與耗時（單張耗時含等待，目標 ≤2 分鐘）。
5. 出總分表，兩邊差距 **≥1 分**才考慮換主力引擎，否則維持現況（gpt-image-2，已建 ChatGPT 專案與知識庫）。

**驗收指標**：全數張數完成並有分數與成本紀錄；四至六項總分差距明確（≥1 分）或明確接近（<0.5 分）——兩種結果都算有結論，只有「沒跑完」才算失敗。

**停損條件**：出圖或評分拖過 2 天仍沒跑完，縮成 1 個案場×2 張先出小結；若兩邊差距在 0.5 分內，直接維持現用引擎（gpt-image-2／現有 ChatGPT 專案），不再加測。

**提醒**：兩邊皆無成果圖佐證的來源結論不可直接採信，本測試的價值就在於補上如菓自己的第一手數據。

## F｜出圖流程配套：提示詞優化／品質檢查／標籤與版本管理（報告① 第 12 條）

**來源**：報告① 第 12 條，Azure-Samples/visionary-lab——把出圖流程拆成三段配套，不是新引擎，是流程紀律。

**三段內容**：
